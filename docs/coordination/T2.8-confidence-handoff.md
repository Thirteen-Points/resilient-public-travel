# T2.8 置信度展示接入（给 A）

这只是审核辅助分数，不是事件已被证实的概率，也不会自动发布事件。A 读取现有 Event 的 `confidence` 绘制数值／进度条，读取 `confidence_factors` 展示原因，读取 `audit_log[].confidence_after` 按时间播放 0.20 → 0.55 → 0.90 动画；同时读取 `status`、`reviewed_by`，只有审核流程产生的 `published` 才显示为已发布。

| 阶段 | 证据条件 | 分数 |
|---|---|---:|
| 初始 | 一条相关、未经核实的报告 | 0.20 |
| 多源一致 | 至少两个不同独立来源，由上游明确判定指向同一事件且相互同意 | 0.55 |
| 官方确认 | 已核实、与同一事件相关的真实官方公告；不含 HKO 不相关警告或 ETA 推断 | 0.85（审核前） |
| 人工确认 | 审核员确认后再加 0.05 | 0.90 |

若出现与该事件相关的矛盾证据，扣 0.15，并显示“信息有矛盾，待核实”。不要仅凭 `confidence >= 0.60` 把卡片标为已发布。分数下降或审核未完成时，继续按真实 `status` 展示。

因子账本按 `weight × score` 求和；`stage_cap` 和 `source_conflict` 是**减项**，其余是加项。`official_floor` 是单条已核实官方公告直达 0.85 时的补足量。这些因子只解释计算，不是新的 Event 字段。`03-contracts.md` 的示例权重按乘法得到 0.95，而示例总分为 0.90；当前计算以阶梯表及 T2.8 验收分数为准，未改共享契约或种子。
