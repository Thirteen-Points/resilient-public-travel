## 优先级说明

- `必做`：主链、阶段交付、合规底线、三亮点或最终提交所需。
- `应做`：风险文档 §3 中优先裁剪顺序 1–5 对应的独立任务，以及性能、成本等增强项。
- `可选`：明确可延后的自动过期、实时重规划和非高峰/假日场景。
- T3.1、T3.5、T4.2 等同时包含核心与可裁剪子范围的卡片保留较高优先级，并在正文注明渡轮、小巴或第三预设的可裁剪边界。

## 维护命令

先把有项目仓库权限的 GitHub token 放入当前进程的 `GITHUB_TOKEN`，再从仓库根目录运行：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/sync_github_tasks.ps1
```

只预览、不访问 GitHub：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/sync_github_tasks.ps1 -DryRun
```

不要把 token 写入文件、提交到 Git，或粘贴进 Issue。
