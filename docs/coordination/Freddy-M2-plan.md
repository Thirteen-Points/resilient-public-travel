## 已确认的接口风险与处理方向

1. **事件状态不同步**：`backend/app/main.py` 的 `GRAPH_ACTIVE_STATUSES` 包含 `updated`；`GET /api/events/published` 只返回 `published`。前端用后一集合绘制影响。需 B/C 决定保留最后审核版本，还是编辑后暂不生效；A 随权威策略更新。不要只在前端将 updated 当作 published，因为编辑内容可能未获再审核。
2. **公开事件被审核读失败拖住**：`useLiveSession.ts` 将受保护的 `getEvents()` 与公开 `getPublishedEvents()` 放在同一个 `Promise.all`；前者失败会丢掉后者本轮成功结果。分开读取及错误状态，保证普通访问者看到有效事件。
3. **审核令牌做法与交接冲突**：前端读取 `VITE_REVIEW_TOKEN`，SSE 把它放查询参数；当前后端支持该参数，但 B 交接明确禁止 URL 传令牌。公网采用受信代理/会话方案，密钥留服务端；受控本地演示可用临时内存凭据与带头的 streaming fetch，重连保留审计游标，不打包进 Vite 环境变量。
4. **运行文档过时**：根 README 的“routes/sim/AI endpoints will be added”、前端 README 的 M0-only 描述、B README 的旧配置和客户端限制必须逐项核对后更新，不能整段复制。
5. **演示数字过时**：`07-demo-acceptance.md` 中路线时间、0.90、分流比例和缺口数字属于计划/示例。当前 B 的三源 0.55 经审核可达到 0.60；展示真实服务输出，不把 seed 0.90 或预计算模拟数字说成真实事件验证。
