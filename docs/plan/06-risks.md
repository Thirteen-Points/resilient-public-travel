## 3. 砍单顺序（**提前约定**，避免当天争吵）

**优先级用词（全项目统一，避免和阶段名 P0–P4 混淆）**

| 用词 | 含义 | 工时 |
|---|---|---|
| **必做** | 下方「绝不允许砍」清单 + 各阶段交付物清单（`05`）里的条目 | ≈ 210 人时 |
| **应做** | 砍单表顺序 1–5 | ≈ 90 人时 |
| **可选** | 砍单表顺序 6–9 | ≈ 60 人时 |

> 77 张卡全部做 ≈ 360 人时 > 可支配的 200–240 人时 ⇒ **默认只做「必做」**。10/11（M3）按实况决定是否启动「应做」。

### 绝不允许砍（砍了项目不成立）
1. 事件 → 受影响区段关闭/降权 → 替代路线重算 → **地图变色 + 路线卡片刷新**这条主链；
2. 路线卡片上的 **来源 / 更新时间 / 免责声明**（合规底线）；
3. 至少 **2 个画像**的首选差异（"懂个人"的最小证明，其中一个必须是轮椅用户）；
4. 1 万人仿真的 **"有引导 vs 无引导"对比**（"会分流"的最小证明）；
5. 数据真实性分级与出处台账。

### 按顺序砍（从最先砍到最晚砍）
| 顺序 | 砍什么 | 代价 | 替代说法（PPT 里怎么讲） |
|---|---|---|---|
| 1 | 移动端适配 | 手机上丑 | "演示针对桌面大屏优化" |
| 2 | AI 对话面板（T6.8） | 少一个交互亮点 | "AI 用于事件结构化与偏好解析，不在对话层堆砌" |
| 3 | 碳排放评分 | 少一个维度 | "预留了碳维度，因数据可靠性问题暂不展示" |
| 4 | 渡轮腿（天星小轮） | 少一条混合模式路线 | "已建模，演示场景中未触发" |
| 5 | 小巴腿（481B） | 少一种模式 | 同上 |
| 6 | 第三种偏好预设（少换乘） | 少一个预设 | 保留最快/最稳两个 |
| 7 | 实时重规划触发（T5.8） | 少一个动态画面 | "重规划在事件更新时触发（演示手动）" |
| 8 | 第四个事件源 | 事件源变 2 个 | 按实际说明 |
| 9 | 非高峰/假日场景 | 只演工作日早高峰 | "服务日历已建模，演示聚焦早高峰" |

**砍单纪律**：任何一次砍单必须①在看板写一条记录；②同步更新 `07` 的演示脚本；③在 PPT 的"已知局限"页里如实列出。

## 4. 合规、伦理与诚实性（答辩必被问）

| 主题 | 我们的做法 |
|---|---|
| **数据来源** | 只用官方开放数据（data.gov.hk、天文台、港铁公开 API）+ 自建模拟数据；每条数据在 `data/PROVENANCE.md` 有出处与查询日期 |
| **不使用个人隐私** | 不采集姓名/账号/精确位置历史；画像由用户自己选；上传 LLM 的只有去标识的结构化偏好 |
| **社媒数据** | 演示用**模拟流**并明确标注；不抓取受保护平台内容作为产品依赖 |
| **非官方声明** | 每页页脚 + 每张卡片：非官方应急指引、以港铁与运输署公告为准 |
| **模拟数据的边界** | UI 徽标三色分级（真实/推算/模拟），卡片可展开查看每条数据的等级 |
| **无障碍的诚实** | 若某路线无法服务轮椅用户，明确显示"不适合轮椅使用者"而不是回避；不宣称已获无障碍认证 |
| **不宣称城市级调度** | 分流是"信息引导 + 负载模拟"，不是真实调度系统；PPT 明确写出来 |
| **开源与许可** | 前端库（Leaflet/React）、底图（OSM/CARTO）均保留署名；仓库加 LICENSE 与致谢页 |

## 5. 团队风险的具体对策

| 风险 | 对策 |
|---|---|
| 意见分歧 | 有数据用数据；没数据由 **A（流程负责人）拍板**并在 24 h 内记录理由，不反复讨论 |
| 某人卡住 2 小时 | **立刻在群里求助**（卡住 2 小时 = 必须喊人，这是规矩，不是丢脸） |
| "做完了没事干" | 从 `04` §4.4 的"反向测试"里挑活；或去补 `data/PROVENANCE.md` 与文案 |
| 士气下降 | 每周日 dry-run 后固定 10 分钟"本周最爽的一件事"；确保每周都有**可见进展**（能录进视频） |
| 周末冲突（9/26、10/1 假期） | 这两天的任务量减半，只安排 ⭐ 任务与"看/核"类任务 |
