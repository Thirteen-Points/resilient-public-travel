## 1. 一句话说清我们在做什么

**当港铁东铁线"大围 → 金钟"走廊的某个区段中断或运力骤降时，本平台把多源信号变成可信事件、把事件变成替代路线、再按"个人偏好 + 群体运力"把乘客重新分配到地铁 / 巴士 / 小巴 / 步行 / 渡轮的组合上。**

工作名 **ResilientRoute**（暂定，A 可改）。交付形态：**一个网页**。周期：**2026-09-21 → 10-18（10/04 interim 提交）**。

## 6. 十条必须记住的事实（PPT 与答辩靠这些数字）

1. 走廊 6 站：大围 → 九龙塘 → 旺角东 → 红磡 → 会展 → 金钟。
2. 东铁过海段 2022-05-15 通车后，大围→金钟直达约 **17 分钟**。
3. 东铁 9 卡定员约 **2,845 人** ≈ **20 辆双层巴士**（约 137 人/辆）。
4. 东铁早高峰单向运力 ≈ **5.3 万人/小时**。
5. **沙田往港岛的过海巴士早高峰载客率已 >90%**（982X）→ **把地铁乘客倒给巴士在物理上不成立**，这是本项目最核心的论证。
6. 唯一全日直达金钟/中环的沙田过海线是 **182**；982X / 985 系列**只开平日早晚高峰单向**。
7. **88K 疑已取消**（2025-08-04）、80M 已建议取消；**680/681/682/307/673/978/968/948X 不服务大围**（原方案里的这些线路必须剔除）。
8. 全港只有 **4 辆低地台小巴**，且**不在大围、无过海小巴** → 轮椅用户必须硬过滤小巴。
9. 港铁**没有官方 GTFS，也没有服务状态 API** → 事件源用：天文台警告（真实）+ 港铁到站异常（真实）+ 用户上报 + 社媒模拟流 + **人工注入兜底**。
10. 底图/模型/部署全部有降级链；**演示断网也要能演完**（离线包 + 预计算 + 录屏）。

## 8. 最容易翻车的三个点（提前说，别当天才发现）

1. **替代运力远小于中断运力** → 不要把叙事写成"我们解决了拥堵"。正确叙事：**减少浪费、错峰、就近分流、如实报告缺口**（`01` §2.2、`07` Q4）。
2. **AI 越界** → 一旦让 AI 产生数字或路线，答辩会被一句话问倒。**硬规则：AI 只做三件事，数字全部来自确定性引擎**（`02` §5）。
3. **三亮点只做出来、没做达标** → 10/11 必须按 `07` §3 逐条测量并留证据；不达标就按 `06` §3 砍掉并在 PPT 里如实列进"已知局限"。

## 9. 术语表

| 术语 | 含义 |
|---|---|
| **走廊（Corridor）** | 大围—金钟六个东铁车站及其 800 米步行圈 |
| **接入点（Access Point）** | 步行圈内的地铁站入口 / 巴士站 / 码头，路线的起终点 |
| **事件卡（Event Card）** | 结构化的中断事件（线路、方向、受影响区段、时间窗、严重度、置信度、来源） |
| **置信度（Confidence）** | 0–1 的可信度评分，由来源权威性/多源一致/物理一致/人工确认四因子加权 |
| **降权 / 关闭（Degrade / Close）** | 受影响区段在图上的 `capacity_factor` 降低或归零 |
| **候选路线（Candidate）** | 引擎生成的约 10 条差异化替代方案 |
| **个人路线（Personal Top-3/5）** | 经硬约束过滤与个人权重排序后给该用户的路线 |
| **运力水桶（Bucket）** | 每条路线的可用运力（班次 × 单车载客 × 满载率上限），按容量从大到小分配需求 |
| **运力缺口（Unstoppable Demand）** | 所有替代路线装满后仍装不下的需求量，**必须如实显示** |
| **真实 / 推算 / 模拟（real / real-derived / simulated）** | 数据真实性三级，UI 用三色徽标区分 |
| **AI 边界（AI Boundary）** | AI 只做"读文本、读偏好、说人话"，不产生数字与路线 |
